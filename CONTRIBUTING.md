Contributing to Electric Money ⚡

Thanks for your interest in Electric Money!

The project is still in an early experimental stage, and contributions are very welcome.

You don't need to be an expert in blockchain to participate. Ideas, testing, documentation, security research and code contributions can all be useful.

Ways to contribute

💻 Code

You can contribute improvements to:

- blockchain consensus
- Proof of Work
- networking
- transaction validation
- cryptography
- wallet software
- mining software
- Layer-2 research
- performance
- testing

🔐 Security

Security research is especially valuable.

If you discover a potential vulnerability, please follow the process described in "SECURITY.md" rather than publicly exposing an exploitable vulnerability immediately.

🧪 Testing

Testing the protocol under unusual conditions is extremely useful.

Examples include:

- malformed transactions
- invalid blocks
- chain reorganizations
- competing miners
- network failures
- timestamp manipulation
- high transaction volumes
- P2P attacks
- unusual wallet states

📚 Documentation

Documentation improvements are also welcome.

Clear explanations of the protocol make it easier for new contributors to understand and review the project.

Before contributing

Please keep in mind that Electric Money is experimental.

Consensus rules are particularly sensitive. A seemingly small change can alter the behavior of the entire network.

For consensus-related changes, please explain:

1. What problem the change solves.
2. Why the current behavior is insufficient.
3. How the proposed change affects consensus.
4. Whether it changes monetary policy.
5. Whether existing nodes would remain compatible.

Pull Requests

When submitting a pull request:

- Explain what you changed.
- Explain why you changed it.
- Keep changes focused where possible.
- Add tests for new functionality.
- Avoid unrelated modifications.
- Clearly identify consensus-changing modifications.

For security-sensitive changes, explain the threat model and the attack being addressed.

Issues

Issues are welcome for:

- bugs
- security concerns
- protocol discussions
- feature proposals
- performance problems
- documentation improvements

Before opening an issue, please check whether a similar issue already exists.

Discussion

Electric Money is intended to be an open experiment.

If you disagree with a design decision, that's completely fine.

Constructive criticism, alternative proposals and independent analysis are encouraged.

The goal is not to assume that the current design is perfect.

The goal is to make it better.

Development philosophy

A few principles are especially important:

Security before convenience.

Deterministic consensus before optimization.

Transparent discussion before assumptions.

Test before deployment.

Thanks for helping build Electric Money. ⚡
